# 上下文、工作记忆与证据回读

本机制接入正式聊天页面使用的 `/runs` 通用助手及论文调研流程。旧 `/completion` 保留原有兼容逻辑。LangGraph 检查点保存完整执行状态，下面的上下文组装只改变送给模型的视图，不删除检查点消息或工具账本。

## 每次模型调用

1. 计算系统指令、工具参数 schema、输出 schema、消息和工具结果的估算 token，预留输出和安全余量。
2. 加入带来源的结构化工作记忆：目标、约束、决定、待解决问题。论文任务还包含当前方向版本、计划、完成的检索及未解决事项。
3. 根据当前问题检索少量相关历史和原始证据。检索材料标记为数据，不能覆盖系统规则或用户最新要求。
4. 保留近期完整对话与最近的完整工具调用组。超出容量时移出较早的完整组，保存其原件及摘要索引；不拆开工具调用与结果。
5. 如果最新请求、有效约束和必要 schema 仍无法容纳，明确返回容量错误。若服务端报告上下文超限，则降低输入预算重试一次模型，工具不会因此重复执行。

新任务不再反复把历史压缩成 200～300 字的全局摘要。旧会话摘要作为有损的历史背景保留，原始聊天记录在首次使用时分批补建检索索引。工作记忆提取与历史摘要产生的内部模型文本不会作为聊天回答流出。

## 容量配置

不需要修改私有模型配置即可启用。可选环境变量：

| 环境变量 | 默认值 | 作用 |
|---|---|---|
| `AGENTCHAT_CONTEXT_TOKENS` | `32000` | 应用采用的上下文容量上限 |
| `AGENTCHAT_CONTEXT_OUTPUT_TOKENS` | `4096` | 输出预留，最多采用容量的四分之一，并受模型 profile 的输出上限约束 |
| `AGENTCHAT_MODEL_CONTEXT_LIMITS` | `{}` | 按模型名设置容量，例如 `{"my-model":64000}` |

存在模型 profile 时还会采用其中较小的输入容量。额外预留 10% 容量（至少 512 tokens）作为误差余量。文本计数对中英文采用不同估算，包含工具 schema；这不是提供方精确 tokenizer。多模态输入还保留媒体估算余量，不能保证任意大小的图片或视频均可装入。服务端实际超限会触发一次额外压缩；不可恢复的过大输入会明确报错。

默认单条大文本工具结果超过约 2000 个估算 token 后转存，模型获得预览、原件 ID、哈希和读取方法；小容量模型会采用更低阈值。账本仍保存完整工具结果，恢复时可以重新构造预览。转存失败不会把已确认成功的外部写操作误标为结果不确定。

## 工作记忆与修改方向

每轮对用户输入进行一次有容量与时间限制的结构化提取；每条记录保留用户逐字引文和原始输入引用。提取出的引文必须确实出现在该轮输入中，否则不采用。模型判断用户明确替换旧要求时，旧条目标记失效，保留旧版本供核查。研究方向调整也单独建立记忆版本。

提取不可用时保留本轮原始要求作为待整理条目，不凭空删除旧约束。持续有效的条目不受普通历史摘要裁剪；过多有效约束会触发明确的容量错误。用户仍需核查语义提取是否正确，原文匹配并不保证模型对撤回含义的判断完全正确。

论文任务在恢复及阶段推进时更新结构化进度；研究方向的新版本优先于旧方向和旧历史。子 agent 保持独立、限范围的上下文，只有确有独立工作时才委派，主 agent 统一核验来源。

## 检索与原文工具

通用助手具有两个只读工具，用户无需手动选择：

- `search_context(query, limit=5)`：搜索本会话的原始聊天、大工具结果、检索记录、论文提取文本及压缩前记录；返回片段、原件 ID、页码、字符偏移、哈希及来源版本。
- `read_evidence(artifact_id, start=0, max_chars=6000, page=null)`：按原件编号、字符偏移或页码读取原文。单次返回受容量限制，返回的 `end` 可作为下一次 `start`。

数据库层同时检查用户与会话归属，不能通过传入其他会话的原件 ID 读取内容。删除会话时同时清理新增上下文原件、片段、FTS 索引和工作记忆。

SQLite 优先使用 FTS5，额外建立中文二字词索引；无 FTS5 的 SQLite 或其他业务数据库使用转义关键词查询。初版是关键词检索与重排，未引入向量服务；同义改写的召回仍有限。FTS 候选及返回片段有上限，不能声称穷尽全部相关记录。

## 论文阅读

PDF 不再固定只读取前 20 页：提取上限为 300 页或 200 万字符，文件仍限制 12 MB。超限、扫描件及身份不匹配会记录限制。提取文本保存到业务数据库，并保存访问地址及原文件哈希；没有额外保存 PDF 二进制文件。

分析前在已提取全文中按研究方向及方法、数据集、实验、局限性选择逐字片段，保存页码与偏移。报告区分提取范围与实际分析片段；不能把已提取全文等同于全文已分析。原文匹配、页码检查和语义核验继续执行。JSON 输入按完整字段或候选裁剪，超过容量时保存原始输入引用，不直接截断 JSON 字符串。

## 持久化与诊断

新增三张业务表：`context_artifact`（不可变原件）、`context_chunk`（检索片段）、`context_memory`（追加式版本记忆）。大型文本暂存在业务数据库，适合当前单机规模；未来可在保留原件 ID 与哈希的前提下改为文件或对象存储。备份仍需包含业务数据库与 LangGraph 检查点文件。

`GET /api/v1/runs/{id}/context` 返回该任务的工作记忆、原件清单及容量轨迹，需登录并拥有会话。轨迹包含估算输入大小、输出预留、移出消息数、召回原件编号和摘要引用，不记录隐藏推理。执行事件 JSONL 导出也包含这些轨迹。模型实际 token 使用沿用现有用量回调，记忆提取及摘要调用同样计入。

回归场景见 `tests/test_context.py`：长历史召回、中文检索、精确原文回读、容量限制、约束修改、来源隔离、长 PDF 后部证据、内部记忆流过滤，以及真实 LangGraph 中断后复用已保存工具结果。测试使用模拟模型与临时 SQLite，不是线上模型质量评测。
